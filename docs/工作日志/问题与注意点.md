# 问题与注意点

## sparkDash 时间与 Token 口径

- `history.hour` 是 UTC 小时桶，按 Asia/Shanghai 00:00–24:00 选取，不能使用滚动24小时或 UTC 日累计替代。
- 缓存是 prompt 输入的子集；总量 = prompt + completion。多 Spark / 端口同模型相加。
- 小时保留期72小时，过期拒绝补报。只存有流量桶，缺桶可能是零或监控缺失；不得保证持续覆盖。

## 公开数据与身份

- 数字 GitHub 作者 ID 决定身份，正文不能指定其他作者。同名微信昵称不合并。
- 用户只能以自己有权公开的实例报名；不能把共享实例总量描述为个人消费。
- 本机请求私有源，平台只接收汇总；地址、令牌、节点和完整响应必须留在本地。
- 关闭报名后下一次成功构建才移除榜单；关闭不等于删除公开 Issue 历史。

## 开发与发布

- 开放 Issue 的 JSON 边界必须捕获 RecursionError，不能让恶意普通 Issue 阻断整个重建与撤回。
- Linux / macOS 定时任务要保存 XDG_CONFIG_HOME；交互 shell 的临时 token 环境不自动传入计划任务。
- 自建站生成命令必须明确传入 `connect --repo`，避免误报到默认仓库。
- 演示标识和真实 fetch 加载状态必须一致，不能在加载竞态下混合来源。
- 新仓库先配置 Pages workflow 模式，再运行部署；首个 push 的配置生效竞态可在启用完成后重跑。

## 私网源的代理与凭据复用

- Python urllib 会继承系统代理；私网探测可能返回代理502，即使 curl 认证状态可达。采集器显式使用空ProxyHandler直接连接。
- 已有私有.env可用 --token-env-file 复用；仅解析白名单令牌变量的字面值，要求POSIX0600，不执行配置文件、不复制密钥。调度器通过配置路径读取同一文件。
